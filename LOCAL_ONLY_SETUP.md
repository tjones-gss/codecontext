## Quick Start (5 Minutes)

### 1. Install Dependencies

```bash
cd codecontext
npm install
```

### 2. Configure for Local-Only Mode

```bash
cp .env.example .env
```

Edit `.env` and set:

```env
# Disable AI - use local analysis only
USE_AI=false

# Disable embeddings - use keyword search only
EMBEDDING_PROVIDER=none

# SVN Configuration (still needed for history)
SVN_REPO_PATH=\\\\LocalCobolSearch\\trunk\\cobol\\fujsource
SVN_USERNAME=your_username
SVN_PASSWORD=your_password

# Source Directories
COBOL_SOURCE_DIR=\\\\LocalCobolSearch\\trunk\\cobol\\fujsource
```

**That's it!** No API keys, no Claude, no Ollama, no cloud services.

### 3. Build and Run

```bash
npm run build
npm start
```

You'll see:

```
===========================================
   CodeContext Live - Starting Up
===========================================

Configuration:
  ✅ AI Mode: DISABLED (using local rule-based analysis)
      100% local, no external APIs, completely FREE!
  ℹ️  Embedding Provider: none

...
```

### 4. Test It

```bash
curl -X POST http://localhost:3000/api/context/markdown \
  -H "Content-Type: application/json" \
  -d '{"filePath": "./examples/sample-files/SCR100.cbl"}'
```

You'll get a complete context summary generated entirely locally!

## How It Works

### Local Rule-Based Analysis

Instead of using AI, CodeContext Live uses **smart heuristics** to analyze your code:

#### 1. **Purpose Detection**

```typescript
// Detects CICS programs
if (code.includes('EXEC CICS')) {
  purpose = "CICS transaction program for screen interactions"
}

// Detects batch programs
if (code.includes('ACCEPT') && code.includes('DISPLAY')) {
  purpose = "Batch processing program with console I/O"
}

// Detects database programs
if (code.includes('EXEC SQL')) {
  purpose = "Database program with SQL operations"
}
```

#### 2. **Conflict Detection**

```typescript
// Checks for hardcoded values
if (code.includes('= "PROD"')) {
  conflicts.push("Contains hardcoded values")
}

// Checks for TODO comments
if (code.includes('TODO') || code.includes('FIXME')) {
  conflicts.push("Contains TODO/FIXME comments")
}

// Checks for SQL injection risks
if (code.includes('EXEC SQL') && !code.includes('PREPARE')) {
  conflicts.push("Potential SQL injection risk")
}
```

#### 3. **Code Quality Analysis**

```typescript
// Comment ratio
commentRatio = (comments / totalLines) * 100

if (commentRatio < 5%) {
  notes.push("⚠️ Low comment ratio - consider adding documentation")
} else if (commentRatio > 30%) {
  notes.push("✅ Well-documented code")
}

// Complexity
if (totalFunctionCalls > 50) {
  notes.push("⚠️ High complexity - many function calls")
}
```

#### 4. **Related Files (Keyword Matching)**

Instead of AI embeddings, uses **Jaccard similarity**:

```typescript
// Tokenize both files
tokensA = tokenize(fileA)  // ["customer", "account", "balance", ...]
tokensB = tokenize(fileB)  // ["account", "update", "balance", ...]

// Calculate similarity
intersection = tokensA ∩ tokensB  // ["account", "balance"]
union = tokensA ∪ tokensB         // ["customer", "account", "balance", "update"]

similarity = intersection.size / union.size  // 2/4 = 0.5
```

Files with high similarity are considered "related."

## FAQ

### Q: Is local analysis really good enough?

**A:** For many use cases, YES! Especially if:
- Your code has good naming conventions
- You need basic context (who modified, what calls what)
- You're working with well-structured legacy code

Try it first. Upgrade to AI only if needed.

### Q: How does keyword search compare to embeddings?

**A:**

- **Embeddings:** Find semantically similar code ("getUserAccount" matches "fetchCustomerData")
- **Keywords:** Find literally similar code (must share tokens)

For legacy codebases with consistent naming, keywords work fine.

### Q: Can I run this on a Raspberry Pi?

**A:** Yes! CodeContext Live in local-only mode uses minimal resources.

### Q: What about performance with huge codebases?

**A:** Local analysis is actually **faster** than AI:
- AI: 1-2 seconds per file
- Local: <100ms per file

For 10,000 files:
- AI: ~3 hours to analyze all
- Local: ~15 minutes to analyze all

### Q: Does "local-only" mean no internet at all?

**A:** You can choose:
- **Full offline:** Set `SVN_REPO_PATH` to local path
- **Hybrid:** Use network SVN for history, but analysis is still local

### Q: Can I customize the analysis rules?

**A:** Yes! Edit `src/services/local-analyzer.ts` to add your own heuristics:

```typescript
// Add custom rule
if (code.includes('MY-COMPANY-PATTERN')) {
  purpose = "Custom company-specific program type"
}
```

### "Related files seem random"

**Solution:** Keyword matching needs good naming conventions. Files with similar names/tokens will be considered related. This works well for well-organized codebases.

### "Can I make the analysis smarter?"

**Solution:** Yes! Edit `local-analyzer.ts` and add your own rules based on your codebase patterns.
